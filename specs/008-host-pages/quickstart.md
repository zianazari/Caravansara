# Quickstart: صفحه‌های میزبان در سایت

## پیش‌نیاز

```sh
docker compose -f docker-compose.yml -f e2e/compose.e2e.yml up -d --build
```

هیچ داده‌ای پاک نمی‌شود، و `-v` به کار نمی‌رود.

## ۱. تست‌های خودکار

```sh
cd frontend && npm run lint && npm run typecheck && npm run format:check && npm test
cd e2e && npx playwright test        # host.spec.ts (the whole host path in Chrome), theme.spec.ts with the host pages
cd backend && uv run pytest tests/test_openapi_contract.py   # the API did not change (SC-006)
```

**انتظار:** همه پاس می‌شوند، و `backend/openapi.json` در `git diff` نیست.

## ۲. دستی در مرورگر

| گام | انتظار |
| --- | --- |
| وارد‌نشده، «میزبان شوید» در سرصفحه | ورود، سپس `/fa/host/new?step=1` |
| ساخت با ۸ گام | پیشرفت «گام n از ۸»؛ فیلد نادرست پیام کنار خودش دارد؛ back مرورگر به گام قبل می‌رود؛ با تازه کردن صفحه پاسخ‌ها می‌مانند |
| گام مکان، تهران | نقشه روی تهران باز می‌شود؛ پین با کشیدن جابه‌جا می‌شود |
| گام قیمت، ۲٬۵۰۰٬۰۰۰ تومان | در API، `price_per_night` برابر `25000000.00` با ارز `IRR` |
| گام عکس، دو عکس | «ارسال برای بازبینی» غیرفعال است، با پیام «دست‌کم ۳ عکس» |
| یک فایل ۱۲ مگابایتی، یا متنی با نام `.jpg` | پیش از ارسال رد می‌شود |
| سه عکس، سپس ارسال | پیشرفت هر عکس؛ سپس صفحه‌ی آگهی با «در انتظار تأیید». در صف مدیر (Swagger: `GET /admin/listings/pending`) هست، و در جستجو نیست |
| تأیید با Swagger، سپس عوض کردن قیمت | بی هشدار ذخیره می‌شود؛ آگهی فعال می‌ماند |
| عوض کردن عنوان | هشدار «تا تأیید دوباره پنهان می‌شود»؛ پس از تأیید، «در انتظار تأیید» |
| رد با Swagger و دلیل | دلیل در صفحه‌ی آگهی و «ارسال دوباره» |
| حذف عکس وقتی ۳ عکس هست | دکمه غیرفعال است، با توضیح |
| `/fa/host/listings/<آگهی کس دیگر>` | «یافت نشد» |
| همه در ۳۲۰ پیکسل و در `/en` | بی اسکرول افقی؛ چپ‌به‌راست درست |

## ۳. زمان‌ها

- **SC-005:** یک عکس ۵ مگابایتی روی stack محلی، از ارسال تا دیده شدن در آگهی، کمتر از ۵ ثانیه. با Playwright اندازه گرفته می‌شود.
- **SC-001:** یک کاربر تازه، بی راهنما، روی گوشی، آگهی کامل با سه عکس در کمتر از ۱۰ دقیقه. با یک انسان. نتیجه در `specs/008-host-pages/measurements.md`.
