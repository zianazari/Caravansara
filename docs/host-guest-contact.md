# لغو رزرو و تماس با مهمان از پنل میزبان

در بخش «رزروها»ی هر اقامتگاه، میزبان نام و ایمیل مهمان را می‌بیند. لینک ایمیل برنامهٔ ایمیل میزبان را باز می‌کند؛ شمارهٔ موبایل ثبت‌شده هم با لینک تماس نمایش داده می‌شود؛ مهمان شمارهٔ میزبان را در جزئیات سفر می‌بیند. [قرارداد شمارهٔ موبایل](phone-contact.md). ارسال پیام یا ایمیل خودکار از این دکمه انجام نمی‌شود.

میزبان می‌تواند رزرو `pending` یا `confirmed` را فقط پیش از روز ورود به وقت شهر اقامتگاه، با تأیید نهایی لغو کند. تاریخ‌ها پس از لغو آزاد می‌شوند؛ مبلغ‌ها و سابقهٔ رزرو حفظ می‌شوند. قاعدهٔ فعلی پرداخت شبیه‌سازی‌شده و بدون جریمه/بازپرداخت پابرجاست. وضعیت فهرست پس از موفقیت تازه می‌شود و اطلاعات تماس برای هماهنگی پس از لغو باقی می‌ماند. رزرو شروع‌شده، پایان‌یافته، منقضی یا لغوشده دکمهٔ لغو ندارد؛ API وضعیت و تاریخ را دوباره بررسی می‌کند.

## قرارداد و دسترسی

- `BookingOut.guest_contact` شامل `full_name`، `email` و `phone_number` اختیاری است و فقط به مالک اقامتگاه همان رزرو برمی‌گردد. برای پاسخ مهمان خالی است؛ اعضای دیگر اجازهٔ خواندن رزرو یا فهرست رزروهای میزبان را ندارند. فهرست مدیریت قرارداد مستقل خودش برای اطلاعات مهمان را دارد.
- `BookingOut.can_cancel` از نقش بیننده، وضعیت رزرو و روز محلی ورود محاسبه می‌شود. رابط آن را مصرف می‌کند؛ تصمیم نهایی با API است.
- فهرست `GET /listings/{id}/bookings` و جزئیات `GET /bookings/{id}` اطلاعات تماس مهمان را برای میزبان مجاز برمی‌گردانند. پاسخ مسیرهای رزرو `Cache-Control: no-store` دارد؛ این داده‌ها وارد کش عمومی جستجو نمی‌شوند.
- `POST /bookings/{id}/cancel` همان مسیر موجود برای مهمان یا میزبان است. تغییر وضعیت شرطی است؛ درخواست تکراری یا وضعیت تغییرکرده `409 invalid_booking_state` می‌گیرد و دسترسی نامرتبط `404` است.
- اطلاعات تماس برای صفحه‌ها به‌صورت دسته‌ای خوانده می‌شود؛ برای هر رزرو یک کوئری جدا اجرا نمی‌شود.

این قابلیت migration تازه‌ای ندارد. [چت خصوصی](future-work.md) در برنامهٔ آینده است و هنوز ساخته نشده است.
