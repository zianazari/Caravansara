# حذف آگهی توسط میزبان

از migration `0014`، میزبان می‌تواند آگهی خودش را از کارت «اقامتگاه‌های من» حذف کند. دکمهٔ حذف یک پنجرهٔ تأیید با نام آگهی باز می‌کند؛ انصراف هیچ درخواست حذفی نمی‌فرستد. پس از موفقیت، فهرست دوباره خوانده می‌شود. غیرفعال کردن موقت همچنان از حذف جداست.

## قرارداد

`DELETE /api/v1/listings/{listing_id}` با نشست عضو، فقط برای مالک، پاسخ `204` دارد. تکرار حذف توسط همان مالک نیز `204` است. بدون ورود `401`، برای مالک دیگر `403 not_listing_host` و برای شناسهٔ ناموجود `404` برمی‌گردد.

حذف بایگانی است: `deleted_at` ثبت و `is_active` خاموش می‌شود. ردیف آگهی، عکس‌ها، نظرها، سابقهٔ بازبینی و رزروهای قبلی نگه داشته می‌شوند. آگهی از فهرست میزبان، جستجو، علاقه‌مندی‌های عمومی و همهٔ ترتیب‌های صف بازبینی کنار می‌رود. میزبان دیگر نمی‌تواند آن را ویرایش، فعال یا دوباره ارسال کند؛ بازیابی در این نسخه ارائه نشده است.

رزرو تأییدشده یا نگه‌داشت `pending` که مهلتش نگذشته، با `409 listing_has_bookings` مانع حذف است. میزبان باید رزروها را تعیین تکلیف کند؛ حذف هیچ رزروی را خودکار لغو نمی‌کند. رزروهای پایان‌یافته، لغوشده، منقضی و نگه‌داشت‌هایی که مهلتشان گذشته مانع نیستند. مهمانِ دارای رزرو پایان‌یافته همچنان به جزئیات سفر و اقامتگاه خودش دسترسی دارد.

ردیف اقامتگاه هنگام حذف قفل می‌شود؛ ساخت رزرو نیز همان قفل را می‌گیرد. بنابراین حذف و ایجاد رزرو هم‌زمان نمی‌توانند هر دو موفق شوند. تصمیم بازبینی با شرط `deleted_at IS NULL` انجام می‌شود تا مدیر نتواند نسخهٔ بازشدهٔ یک آگهی حذف‌شده را تأیید کند. محدودیت دیتابیس نیز فعال بودن آگهی بایگانی‌شده را رد می‌کند.

## اجرا

پیش از اجرای API جدید، Alembic را تا `0014` ارتقا دهید. تعداد جدول‌های برنامه همچنان ۱۸ است. فرانت‌اند و API باید هر دو به‌روز شوند. داده‌های موجود بدون تغییر باقی می‌مانند چون مقدار پیش‌فرض ستون جدید خالی است.
